## Overview

This folder contains a small C++ OpenGL viewer used to visualize regions/meshes generated by the training runs in `../runs/`. 

The project is built with CMake and fetches GLFW and GLM automatically.

## Prerequisites

You'll need a C++17 toolchain, CMake (>= 3.16) and OpenGL development headers:

- Linux (Ubuntu/Debian): build tools + OpenGL/X11 dev packages
	- Install: `sudo apt-get install -y build-essential cmake git libx11-dev xorg-dev libglu1-mesa-dev libxi-dev libxcursor-dev libxrandr-dev`
- macOS: Xcode command line tools or full Xcode (provides OpenGL framework)
	- Install tools: `xcode-select --install`
- Windows (choose one):
	- Visual Studio 2019/2022 with C++ Desktop workload (MSVC + Windows SDK), or
	- MSYS2 MinGW64 toolchain (GCC): install MSYS2, then in an MSYS2 MinGW64 shell run `pacman -S --needed base-devel mingw-w64-x86_64-toolchain cmake git`

Notes:
- GLFW and GLM are fetched via CMake's FetchContent; no separate installs required.
- On macOS we request an OpenGL 3.3 Core context.
 - Optional: installing Ninja can speed up builds. On Ubuntu/Debian: `sudo apt-get install -y ninja-build`, then export `CMAKE_ARGS='-G "Ninja"'` before running the script.

## Quick start (recommended)

- Linux/macOS:
	- Build + run: `./interface/build_run.sh run`
	- Build only: `./interface/build_run.sh build`
	- Configure only: `./interface/build_run.sh configure`
	- Rebuild (clean + build): `./interface/build_run.sh rebuild`
	- Clean: `./interface/build_run.sh clean`

- Windows (PowerShell or cmd):
	- Build + run: `interface\build_run.bat run`
	- Build only: `interface\build_run.bat build`
	- Configure only: `interface\build_run.bat configure`
	- Rebuild (clean + build): `interface\build_run.bat rebuild`
	- Clean: `interface\build_run.bat clean`

Notes:
- The scripts rely on CMake's default generator by default. To force a specific generator/architecture without using manual commands, set an environment variable before running the script, for example:
	- PowerShell/cmd (Windows): `set CMAKE_ARGS=-A x64` or `set CMAKE_ARGS=-G "MinGW Makefiles"`
	- Bash (Linux/macOS): `export CMAKE_ARGS='-G "Ninja"'`
	The scripts will append `%CMAKE_ARGS%`/`$CMAKE_ARGS` to the CMake configure step.
- On Windows, the batch script will run either `interface\\build\\pinn_interface.exe` (MinGW/single-config) or `interface\\build\\Release\\pinn_interface.exe` (MSVC/multi-config), depending on which exists.
 - On Linux/macOS, if a multi-config generator is used (e.g., Ninja Multi-Config), the bash script auto-detects the `${CONFIG}` subfolder when running.

## Manual CMake build (alternative)

- Linux/macOS:
	- `cmake -S interface -B interface/build -DCMAKE_BUILD_TYPE=Release`
	- `cmake --build interface/build -j`
	- `./interface/build/pinn_interface`

- Windows (MSVC):
	- `cmake -S interface -B interface/build -A x64`
	- `cmake --build interface/build --config Release -j`
	- Run `interface/build/Release/pinn_interface.exe`

- Windows (MSYS2 MinGW64):
	- Open an MSYS2 MinGW64 shell
	- `cmake -S interface -B interface/build -G "MinGW Makefiles" -DCMAKE_BUILD_TYPE=Release`
	- `cmake --build interface/build -j`
	- `./interface/build/pinn_interface.exe`

## Troubleshooting

- Linux: If linking fails with X11, ensure `libx11-dev` and `xorg-dev` are installed.
- macOS: If you have only OpenGL 3.2, you may need to lower the requested version in the code.
- Windows: When using MSVC, the executable is under `interface/build/Release/` for Release configuration.
